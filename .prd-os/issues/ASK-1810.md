# Verifiable green is enforced by verify: no full suite, real path measured, defined vs ran and repeats computed and sealed

## Context

Parent PRD: `https://linear.app/ask-consulting/issue/ASK-1810`

## Acceptance

(1) The check-budget logic lives in `plugins/kipi-dsse/scripts/check_budget.py` as pure functions over a parsed spec dict. Only its CLI `main()` loads `issue_runner._parse_frontmatter`, and it does so lazily, so there is no import cycle. The q-system script, its test and its manifest entry are deleted; nothing else calls them. (2) `issue_runner.py load` writes `"verify_contract": 2` into the state. Rules 3 to 6 apply only when that key is present, so the issue in flight at merge is grandfathered and every issue loaded after merge is not. (3) Before any check runs, `verify` runs `check_budget.full_suite_checks()` (rule 1 of `judge()`) on the snapshot; `is_full_suite` also matches `py.test` and `verify.sh --full=...`. It refuses at exit 2, naming the check, on a full-suite check: `verify.sh --full`, bare `pytest`, or `kipi check`. RED FIRST on a fixture spec carrying `verify.sh --full`. Rule 2 (the check targets the issue's own tree) is not enforced by verify. (4) Real path, measured and not declared. `verify` runs each required check once with `real_path_observer/sitecustomize.py` first on `PYTHONPATH`, and records the allowed non-test `.py` files that were imported (`__file__` at exit), launched (Popen, exec or spawn argv) or exec'd (`co_filename`) at their tracked repo path. It refuses when no required check drove any of them, and names the files. Allowed scripts that are not `.py` are listed as "not observed", never refused. The refusal text states the limits: it sees Python processes only, a child started with a scrubbed env is invisible, and it proves execution at the production path, not that an assertion depended on it. RED FIRST on a fixture whose only check runs a temp-dir copy of the script; the same fixture pointed at the tracked path goes green. A spawn argv counts only when its program is a Python interpreter (basename `python`, `python3`, `python3.N`, or `sys.executable`), and then only its script: the first non-option argument, skipping the values of `-W` and `-X`, and none after `-c` or `-m`. A `.py` argv[0] also counts. RED FIRST on a fixture whose test runs `cp <tracked script> <tmp>` and then the copy. (5) Defined vs ran, computed. For each Python test file a required check names, defined is the AST count of `test*` functions and methods. Ran and skipped are parsed from the runner's own output (`Ran N`, or the pytest summary line). It refuses when ran + skipped < defined, naming the file and both numbers. Ran > defined is recorded, not refused. A check narrowed with `-k` or `::` is recorded as "narrowed" and checked only for ran > 0. Unparseable output for a Python test file refuses; a test file that is not Python is recorded as "not counted". RED FIRST on a fixture test file whose mid-file `unittest.main()` hides the tests below it. Before any check runs, a check that starts pytest or unittest and names no Python test file resolving from the repo root (a directory, `.`, `discover`, a path relative to a `cd`) is refused with 'name the test files this issue changes'; a dotted unittest module that resolves to a file is counted as that file. Unittest `Ran N tests in` lines are read from stderr only. Defined counts `def test*` at module scope and in class bodies at any depth, including under `if`/`try`/`with`, never inside a function body. A named test file that does not parse refuses at exit 2, naming the file and the error. (6) Repeats, computed. After the observed pass, `verify` reruns the required checks until there are N = min(10, floor(1200 / first-pass seconds)) runs in total. It refuses when N < 5, naming the slowest check. Any red in any run is red, reported as k of N. RED FIRST on a fixture check that fails one run in three. `KIPI_VERIFY_BUDGET_S` that is not a finite positive number refuses at exit 2 before any check runs, naming the value. (7) All three results go into `verified_evidence` and are hashed by `_evidence_seal`. `close` refuses on a missing field or a seal mismatch, with the text: "presence and shape are checked; a recomputed seal proves verify wrote them, not that the runner's own count is true." (8) A mutant that drops each of these is killed: the full-suite refusal, the real-path refusal, the defined-vs-ran refusal, the N < 5 refusal, and each sealed field. (9) Calibration before merge: run the real-path observer once on the required checks of the 12 A-only specs and 12 closed A-and-B specs from the 2026-09-18 population measurement. [ASK-1808](https://linear.app/ask-consulting/issue/ASK-1808/design-chain-seal-measures-a-snapshot-so-what-is-measured-is-what-is) must pass. Paste each refusal classified as "copy or stand-in, correct" or "observer blind", and fix every observer-blind refusal before merge. (10) Pasted in the closeout, from verify's own output on this issue: tests defined vs ran for each required-check file, repeats k of N, and the real-path files per check. (11) Stays prose and ungated: the one run of touched test files that are not required checks, the mutant tally, and files x repeats x seconds. Verify does not run those files, so it cannot count them. (12) `amend` sets `verify_contract` to at least the current contract and never lowers it. The observer prints a chained sitecustomize's exception to stderr, as CPython does. (13) NOT MET, carried to ASK-1819: before verify, the contract stamp is an unsealed field in the state file, and a check can write its own observer log line. Contract 2 turns an honest mistake into a refusal and makes forgery a deliberate act; it does not make forgery impossible. Per-file counting is carried to ASK-1820.
