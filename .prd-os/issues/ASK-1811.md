# design-chain: the chain reads the snapshot, not the disk

## Context

Parent PRD: `https://linear.app/ask-consulting/issue/ASK-1811`

## Acceptance

every read of a round file that happens after the snapshot is taken reads `snap.files`, while `design-chain.json` and the owner files still resolve from the live tree by one spelling. `chain_problems()` and `craft_problems()` take the held snapshot when one exists and fall back to disk when called from the passive gate, which holds none. RED FIRST against the real gate, real producers and real chromium: an A -> X -> A watcher that swaps `brief.md` to a good brief at the moment seal's server comes up and restores the bad one after the verdict is written gives exit 0 and a receipt before the fix, and exit 2 with no receipt after; the same watcher on `craft-manifest.json`, injecting a wireframe declaration that exists on disk neither before nor after the seal, does not flip the producer selection. Both pre-fix and post-fix outputs are pasted in the closeout. The passive gate's behavior on an already-sealed round is unchanged, proved by running it over every round already sealed on disk. Not in this issue: the live-vs-snapshot compare ([ASK-1808](https://linear.app/ask-consulting/issue/ASK-1808/design-chain-seal-measures-a-snapshot-so-what-is-measured-is-what-is)), the receipt digest reader (dc-10), `round_declaration()` ([ASK-1808](https://linear.app/ask-consulting/issue/ASK-1808/design-chain-seal-measures-a-snapshot-so-what-is-measured-is-what-is)).
