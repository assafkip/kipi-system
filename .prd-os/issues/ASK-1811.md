# design-chain: the chain reads the snapshot, not the disk

## Context

Parent PRD: `https://linear.app/ask-consulting/issue/ASK-1811`

## Acceptance

Every read of a round file after the snapshot is taken reads the bytes seal holds: seal hands `chain_problems()` the snapshot's copy of the page, so every in-round read, `craft_problems()` included, is rooted in the snapshot, and reads that leave the round map to the live tree through `_live()`, one function. While a seal holds a snapshot, `find_config()` for a path inside that snapshot returns the `design-chain.json` seal loaded (`snap.cfg_path`, the path the producers were given) and never walks again; when that is None the chain refuses "no design-chain.json found", as before. `round_dir_for()` never walks above the snapshot directory. The passive gate holds no snapshot and reads the disk, unchanged. At seal, a page with a logged correction or a sealed source declaration is held to the full chain like any other page: those exemptions are the passive gate's alone, because a seal writes a receipt and a receipt says the chain was measured. RED FIRST against the real gate, real producers and real chromium: an A -> X -> A watcher that swaps `brief.md` to a good brief at the moment seal's server comes up and restores the bad one after the verdict is written gives exit 0 and a receipt before the fix, and exit 2 with no receipt after; the same watcher on `craft-manifest.json`, injecting a wireframe declaration that exists on disk neither before nor after the seal, does not flip the producer selection. The same RED FIRST holds for: a round with no `brief.md` sealed while a complete fake round sits above the snapshot directory; a round sealed by a relative path from its parent; a round sealed through a symlink whose resolved tree carries a more permissive config. Both pre-fix and post-fix outputs are pasted in the closeout. The passive gate's behavior on an already-sealed round is unchanged, proved by running it over every round already sealed on disk. Not in this issue: the live-vs-snapshot compare ([ASK-1808](https://linear.app/ask-consulting/issue/ASK-1808/design-chain-seal-measures-a-snapshot-so-what-is-measured-is-what-is)), the receipt digest reader (dc-10), `round_declaration()` ([ASK-1808](https://linear.app/ask-consulting/issue/ASK-1808/design-chain-seal-measures-a-snapshot-so-what-is-measured-is-what-is)); reads of inputs outside the round (config bytes, owner files, OPEN-DECISIONS, the implements source, sibling briefs, exemplars, vision and specs, grounding file, references/): [ASK-1831](https://linear.app/ask-consulting/issue/ASK-1831).
