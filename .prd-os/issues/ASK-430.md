# Spillover severity provenance: distinguish a defaulted `minor` from an assessed one

## Context

Parent PRD: `https://linear.app/ask-consulting/issue/ASK-430`

## Acceptance

Write the failing tests FIRST. (1) `spillover add` stamps `severity_source: "explicit"` when `--severity` is passed and `"default"` when it is not, and the two are distinguishable in the ledger. (2) `gates run` splits its REPORT line into "assessed" and "never triaged" instead of one "minor-or-untriaged" bucket. (3) Records written before this change carry no `severity_source` and must read as `unknown`, never silently as assessed — this is the test that decides whether the field is honest. (4) `reclassify` sets `severity_source: "explicit"`. Mutation-check each; in particular a mutant that defaults missing provenance to "assessed" must go red, since that is how the field would quietly launder 550 unexamined rows as examined. NOT in scope: any bulk reclassification of the existing population — a mechanical pass stamping a severity nobody read is the same hand-clear in a different coat. Existing rows become measurable, not approved.
