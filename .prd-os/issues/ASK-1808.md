# design-chain: seal measures a snapshot, so what is measured is what is sealed

## Context

Parent PRD: `https://linear.app/ask-consulting/issue/ASK-1808`

## Acceptance

seal copies the round's servable files to a private snapshot (mkdtemp mode 0700, or in-memory), hashes the snapshot, serves THE SNAPSHOT, and points the producers at it. The receipt is written only if the live round's digest equals the snapshot's digest; a mismatch exits non-zero and names the differing paths. Producer verdict files are copied back to the round. RED FIRST: the A -> X -> A watcher from dc-03's final review, run against the real gate, real producers and real chromium; the pre-fix run gives exit 0 and pass, the post-fix run gives non-zero and no receipt, and BOTH outputs are pasted in the closeout. The digest covers every served path; files are skipped by exact NAME (chain records only), never by directory and never by suffix, and a test drops a new file into `gate/` and `checks/` and fails if the digest ignores it. The residual is recorded in the receipt: the same OS user can write to the snapshot mid-seal. The required check runs with `DC_REQUIRE_REAL_PRODUCERS=1`, so a missing playwright FAILS instead of skipping. 10 of 10 repeat runs are pasted, along with tests defined vs tests ran for every file the issue touches. ADDED 2026-09-18 by Sana's triage of the round-1 reviews of 4ab043d7. BOUND (finding-7): the receipt's `__assets__` digest is written here and has no reader until dc-10. What this issue proves is bounded to the seal itself: during a seal, what is measured is what is sealed. After the seal, a subresource swap is caught by dc-10, not by this. UNSERVED FILES (finding-8, finding-9): the in-memory server records every request it answers 404, and seal REFUSES when that set is non-empty, naming each path: the page asked for a file this round does not serve, so the verdict would be about a page missing that file, not about the page. The only exemptions are the closed set the browser requests on its own without the page asking: `/favicon.ico`, `/apple-touch-icon.png`, `/apple-touch-icon-precomposed.png`, `/robots.txt`. Exact names, never a directory and never a suffix, and the set grows only by an issue. Text responses carry `charset=utf-8`, so chromium does not decode the page as windows-1252 and then request a mojibake name. A test proves all three entries refuse: a stylesheet symlinked outside the round, a non-ASCII stylesheet name, and a case-mismatched link (`Shared.CSS` against `shared.css`) that the pre-commit disk server served through APFS. Case is not folded: a static host on Linux does not fold it, so the refusal is the honest answer and the pre-commit behavior was the defect. A population check runs the new refusal against every round already sealed on disk and reports how many would newly refuse; a non-zero count is a finding in the closeout, not a pass. CHAIN RECORDS (finding-10): the live-vs-snapshot compare covers EVERY file in the round except the three this seal itself writes (`standard.json`, `checks/gap.json`, `receipts.json`). The chain records are no longer excluded from the compare, so an A -> X -> A on `brief.md` that leaves the file swapped refuses. The compare's exclusion set and `asset_digest`'s exclusion set are two different lists for two different jobs and are named separately in the code. `round_declaration()` returns the held snapshot's bytes when this seal holds a snapshot, so a `craft-manifest.json` that exists only during the seal cannot decide which producer runs. NOT MET here and carried to ASK-1811: `chain_problems()` and `craft_problems()` still read their chain records from disk after the snapshot is taken, so a record swapped and restored inside the window is caught by neither read; the compare catches only a swap that is left in place. CONFIG (finding-11, finding-14): the fixture's `design-chain.json` sets every value the test relies on to a number that appears nowhere in the producer's `DEFAULTS`, and the test asserts the value out of the verdict entry's own `config` block, so a dropped `--config` changes the recorded number and the test goes red. Mutants M-H (drop `--config`), M-S (`_copy_back` no longer removes a verdict this run did not write) and M-V (`_drop_prior_verdict` never runs) are each killed by a named test. `seal` resolves `design-chain.json` once and passes that path down to `_run_producers`, which no longer calls `find_config` itself. SIGNALS (finding-12): `seal()` installs SIGTERM and SIGHUP handlers that raise SystemExit so the snapshot's `finally` runs, only on the main thread, only over a handler that is `SIG_DFL`, and restores the prior handlers in a `finally`. A test sends SIGTERM and SIGHUP to a live seal, waits for it to exit, and asserts no `dc-seal-*` directory remains in the temp dir; the clean-exit test is named for what it covers. SMALLER (finding-1, 2, 5, 13, 15): immediately after the snapshot is taken, `seal` refuses naming any page absent from it, at exit 2, never a traceback. Each A -> X -> A watcher records WHY its wait loop ended and the test asserts the reason is `listening`; with `seal_is_listening` stubbed to always return False the test goes red. `snapshot_round` refuses when the registry already holds this round. A seal that refused leaves no `pass: true` for its pages in the live `standard.json` (one rollback function, one caller; a FAILING verdict stays, because it agrees with the refusal and `test_dc_served_round.py`, outside this issue's files, reads it after a refused seal). The served-path test probes a file symlink out, a directory symlink, a symlink loop, a broken symlink and an encoded slash.
