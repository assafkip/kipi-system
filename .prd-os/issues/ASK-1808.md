# design-chain: seal measures a snapshot, so what is measured is what is sealed

## Context

Parent PRD: `https://linear.app/ask-consulting/issue/ASK-1808`

## Acceptance

seal copies the round's servable files to a private snapshot (mkdtemp mode 0700, or in-memory), hashes the snapshot, serves THE SNAPSHOT, and points the producers at it. The receipt is written only if the live round's digest equals the snapshot's digest; a mismatch exits non-zero and names the differing paths. Producer verdict files are copied back to the round. RED FIRST: the A -> X -> A watcher from dc-03's final review, run against the real gate, real producers and real chromium; the pre-fix run gives exit 0 and pass, the post-fix run gives non-zero and no receipt, and BOTH outputs are pasted in the closeout. The digest covers every served path; files are skipped by exact NAME (chain records only), never by directory and never by suffix, and a test drops a new file into `gate/` and `checks/` and fails if the digest ignores it. The residual is recorded in the receipt: the same OS user can write to the snapshot mid-seal. The required check runs with `DC_REQUIRE_REAL_PRODUCERS=1`, so a missing playwright FAILS instead of skipping. 10 of 10 repeat runs are pasted, along with tests defined vs tests ran for every file the issue touches.
