# RCA: The meaning check refused correct repairs in three review rounds, each time for a rule outside its exemption list

**Date:** 2026-11-18
**Trigger:** consulting PR #616 round 1 (the carry of kipi PR #843) returned REQUEST CHANGES with three majors, after #843 round 1 returned REQUEST CHANGES and round 2 APPROVE WITH NITS. The round 1 major and two of the three #616 majors are the same class.
**Surface-fix commit:** 2674e243 (round 2 of #843, partial); pending for the #616 findings
**Structural-fix commit:** pending

## What happened

PR #843 added `meaning_check`, which refuses a model revision that changed a number, negation, modal or condition. Round 1 found that rules which order a span rewrite were refused. Round 2 added an exemption list and was approved. The consulting carry review then found the list is still incomplete in production, and that the new catch for the refusal is wired to a module while production injects a `SimpleNamespace`.

## Surface symptom

From the #616 review, executed reproducers:

- `figure-in-post` discarded: `verdict: discarded_replaced ... regenerator raised: revision changed meaning (numbers: -1990 -3 hour)`.
- `voice-style-hedge_count` fix refused: `revision changed meaning (modals: -might)`. 8 of the 13 `voice-style-*` rules `style_feedback` can emit are not exempted.
- `_meaning_refused(port) -> _NeverRaised` against the real `revise_port` namespace, so `MeaningRefused` escapes `gate_and_judge`, `trail["style"]` is never written, and a notice plus Linear ticket is filed.

## Surface root cause

`SPAN_REWRITE_RULES` and `_NUMBER_RULES` are lists of rule names written by hand or derived from `RULE_GUIDANCE` keys. Neither list is the set of rules the producers emit. `_meaning_refused` reads `MeaningRefused` off the injected `revise` object, and the object production injects is not the module.

## Structural root cause

### Root cause #1
The exemption is keyed on rule names, but the authority for "which rules exist" is split across producers (`voicefp_gate.style_feedback`, `figure_free_gate.RULE`, `ending_gate`) that live in the skeleton and in consulting. Every round enumerated the names the reviewer had named, so every round fixed a subset. This is the shape "a property belongs on the token": the property (this rule's fix legitimately changes small words or figures) should be declared by the producer on the violation, not listed in a consumer.
type: implicit-contract

### Root cause #2
Tests built their fixtures from the engine's own module (`types.ModuleType("revise")`, `RULE_GUIDANCE` keys) and not from the producers' real output. A set derived from `RULE_GUIDANCE` cannot fail on a rename, and the injected-object test certified the defect.
type: missing-test

### Root cause #3
The skeleton PR was reviewed and merged before the consulting wiring (`cycle._gate_and_judge_engine`, `post_envelope.revise_port`) was exercised. The consulting carry is the first place the real injected object exists, so production-shaped defects surfaced one repo late.
type: process

## Lessons

- A list of names in a consumer is a patch per round. Put the property on the token the producer emits.
- Build fixtures from the producer's output and from the object production injects.
- Run the consuming repo's review before treating a skeleton PR as done when the change adds an exception that crosses a boundary.
