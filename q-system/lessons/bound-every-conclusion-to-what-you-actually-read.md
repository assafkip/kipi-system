title: Bound every conclusion to what you actually read
date: 2026-08-10
---

A reversed conclusion almost always has the same shape: you opened part of a system, then stated something true only of the whole. Guards that check "did you open this file before claiming about it" pass cleanly here, because you did open a file. The gap is between what you read and how far the claim reaches.

How to apply:

1. Before stating a conclusion, name its scope out loud in the same sentence: "in the two stages I read" rather than "in this pipeline". If you cannot name how many of N components you inspected, you are not ready to conclude.

2. When a chain, pipeline, or set has K members and you read k < K, either read the rest or downgrade the claim to a hypothesis with the unread members listed by name. A named gap survives compaction; a vague hedge does not.

3. Treat a reference that was merely surfaced as unread. An index line, a title in a context banner, a link in a summary, a docstring you skimmed: none of these are the content. Emission into context is not delivery. If a reference matters to the conclusion, open it and record that you did.

4. Make any "read X first" requirement produce an artifact, not an intention. A prose rule that says read-then-act cannot verify itself. Have the read step write something a later step consumes: a scoped notes file, a checklist of sources with a line quoted from each, a plan the work is diffed against. If nothing downstream fails when the read is skipped, the requirement is decoration.

5. Know what your automated grounding checks cannot see, and write it down where you will hit it. Most such checks verify that a source was touched, not that the claim stays inside it. Over-generalization from a real source is the residual class. Handle it with the scope-naming habit above, not by assuming the check covers it.

6. Raise the bar as the output moves outward. An internal note can carry a scoped hypothesis. Anything leaving the system, going to another person, or triggering a decision needs every claim traced to a source you opened in this session, with the scope stated. Do the trace before it leaves, not after someone questions it.

The failure mode is not laziness about reading. It is reading honestly and then letting the conclusion travel further than the evidence.
